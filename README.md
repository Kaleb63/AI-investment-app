# AI Investment Research API

A backend-only investment research application built with FastAPI. It connects to
Plaid investment accounts, retrieves Finnhub market data, calculates transparent
stock and portfolio scores, supports deterministic stock screening, and uses the
OpenAI API only to translate or explain structured financial evidence.

This software is for research and demonstration. It is not investment advice and
does not guarantee performance. It cannot place trades.

## Architecture

```text
API client
    |
    v
FastAPI routes ---- JWT authentication ---- SQLAlchemy / PostgreSQL
    |
    +---- Finnhub service ---- bounded concurrency, retries, TTL cache
    |
    +---- Scoring service ---- deterministic rules and configurable weights
    |
    +---- Plaid service ------ encrypted tokens and user-owned connections
    |
    +---- OpenAI service ----- validated criteria and evidence-only explanations
    |
    +---- Portfolio service -- allocation, sector mix, concentration, HHI
```

Business logic lives under `backend/services`, HTTP contracts under
`backend/schemas`, persistence models under `backend/models`, and API endpoints
under `backend/routes`. The process-local cache and stock-universe provider use
small interfaces so Redis or another provider can replace them later.

## Features

- Finnhub quotes, normalized metrics, company profiles, and historical prices.
- Deterministic equity scores for valuation, growth, profitability, financial
  health, and momentum.
- Configurable scoring weights that must total 100.
- Stock screening with explicit pass, failure, missing-data, and provider-error
  results.
- Finnhub-backed U.S. stock universe with equity/ETF separation, deduplication,
  ticker validation, search, and pagination.
- Concurrent scans with bounded requests, retry/backoff, failure isolation,
  timeout handling, cache metrics, and measured performance fields.
- Natural-language screens converted by AI into a strict Pydantic schema before
  deterministic evaluation.
- Evidence-only AI explanations that do not choose stocks or provide buy/sell
  instructions.
- Portfolio weights, top-three/top-five concentration, HHI, effective position
  count, asset allocation, and sector allocation.
- PostgreSQL-ready persistence for users, Plaid items, saved screens, watchlists,
  analysis history, and scan history.
- Encrypted Plaid access tokens, JWT authentication, password hashing, ownership
  checks, rate limiting, CORS restrictions, trusted hosts, and security headers.
- Watchlist CRUD and watchlist analysis.
- Historical returns, annualized volatility, and moving averages kept separate
  from the fundamental score.
- A broker interface whose order operation intentionally remains unavailable.
- A simulated demo portfolio that uses the real scoring and portfolio pipeline.

## Scoring model

Default category weights are:

| Category | Weight |
| --- | ---: |
| Valuation | 20% |
| Growth | 25% |
| Profitability | 25% |
| Financial health | 15% |
| Momentum | 15% |

Missing categories do not score zero. The weighted score is recalculated from
available categories and `data_coverage` reports the percentage of model weight
supported by available data. Every response includes category scores and textual
reasons generated by deterministic rules.

## Local setup

Create and activate a virtual environment, then install dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

Generate secure values rather than copying the examples:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Put the first value in `SECRET_KEY` and the second in
`PLAID_ENCRYPTION_KEY`. Add provider keys to `.env`; never commit that file.

Initialize and run the API:

```powershell
alembic upgrade head
uvicorn backend.main:app --reload
```

Open `http://127.0.0.1:8000/docs` for interactive API documentation.

## Authentication flow

1. Call `POST /auth/register` with an email and a password of at least 12
   characters.
2. Call `POST /auth/login`, or use the OAuth2 `POST /auth/token` form.
3. Send `Authorization: Bearer <token>` to private Plaid, portfolio, watchlist,
   saved-screen, and history endpoints.

Every database query for a private resource is scoped to the authenticated user.

## Important endpoints

| Endpoint | Purpose |
| --- | --- |
| `POST /screen` | Deterministically screen supplied tickers |
| `GET /stock_universe` | Retrieve filtered equities or ETFs |
| `POST /ai_screen` | Translate natural language, then run the deterministic screen |
| `GET /analysis/{ticker}` | Score a single equity |
| `GET /historical/{ticker}` | Historical return and volatility statistics |
| `POST /create_link_token` | Start authenticated Plaid Link flow |
| `POST /exchange_public_token` | Encrypt and persist a Plaid connection |
| `GET /portfolio_analysis` | Analyze a user's connected portfolio |
| `GET /watchlist/analysis` | Analyze a user's watchlist |
| `GET /demo/portfolio_analysis` | Run a clearly marked simulated portfolio |

## Tests and linting

Routine tests mock or replace external services and do not consume provider API
limits:

```powershell
python -m pytest -q
ruff check backend
```

The recorded verification run on October 17, 2026 passed **140 tests**, with
**0 failures** and **2 skipped** opt-in live OpenAI evaluations. See
[`test-results/README.md`](test-results/README.md) for the environment, coverage,
and machine-readable results. GitHub Actions now runs pytest on pushes and pull
requests and uploads a JUnit results artifact.

### Validated AI explanations

The application calculates scores before requesting an explanation. OpenAI uses
Structured Outputs to select IDs from a catalog of verified statements; it cannot
provide the displayed prose or financial figures. The server validates the
selection and renders each sentence from the original calculations. This prevents
invented values and also prevents reusing a real number for the wrong metric or
unit. The selection approach follows the
[official OpenAI Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs).

Stock explanations always include the overall score, category breakdown,
configured weights, available-data coverage, and missing metrics. Portfolio
explanations include concentration, largest-position weight, allocations, and
missing information. Zero growth and returns are described as flat rather than
negative. Numerical scoring thresholds and weights are unchanged.

Malformed, duplicate, or unknown evidence IDs, extra prose or numeric claims,
refusals, and incomplete responses fail validation. `GET /ai_analysis/{ticker}`
returns HTTP 502 with `invalid_ai_explanation` for invalid output. Optional
portfolio explanations remain `null` on AI failure, while the calculated
portfolio analysis is returned. The `ai_explanation` string contract is unchanged.

The default suite uses synthetic financial fixtures and mocked OpenAI responses;
it does not measure the live model's selection quality or provider availability.
To run the two real-model grounding evaluations with your own OpenAI credentials
(this makes paid API calls):

```powershell
$env:OPENAI_API_KEY = "your-key"
$env:RUN_LIVE_OPENAI_EVAL = "1"
python -m pytest backend/tests/test_live_ai_evaluation.py -q
```

The live evaluations check that every returned paragraph belongs to the original
evidence catalog and every required disclosure is present. They fail if enabled
without an API key. Keep credentials out of source control.

## Benchmarks

The benchmark command records actual results; the repository intentionally makes
no unmeasured throughput claim.

Start small to confirm provider limits:

```powershell
python -m backend.benchmark --sizes 10 --output benchmark-results-10.json
```

Only after confirming the Finnhub plan and rate limits, run:

```powershell
python -m backend.benchmark --sizes 10 100 500 1000 --output benchmark-results.json
```

Each run records duration, attempted and successful stocks, failure percentage,
successful stocks per second, and cache hits/misses.

An actual cold-cache 10-symbol run is recorded in
`benchmarks/2026-09-21-finnhub-10.json`. It successfully analyzed 9 of 10 symbols
in 0.2821 seconds. This is one environment-specific observation, not a general
throughput promise. The 100/500/1,000-symbol runs were intentionally not started
until the Finnhub account's sustained rate limit is confirmed.

## Deployment

`Dockerfile` and `render.yaml` provide one production deployment path. Production
configuration requires:

- a managed PostgreSQL `DATABASE_URL`;
- a long random `SECRET_KEY`;
- a Fernet `PLAID_ENCRYPTION_KEY`;
- provider credentials;
- explicit `CORS_ORIGINS` and `TRUSTED_HOSTS` values.

The container applies Alembic migrations before starting Uvicorn. Set
`AUTO_CREATE_DATABASE=false` in production if desired; migrations remain the
source of truth.

## Limitations

- Finnhub data availability, metric definitions, historical candles, and rate
  limits depend on the account plan. Unsupported data is reported as unavailable.
- The initial TTL cache and request limiter are process-local. Multi-instance
  deployment should replace them with Redis-backed implementations.
- The stock universe is filtered from provider metadata; exchanges can contain
  duplicate share classes and provider classifications can change.
- Sector allocation is partial when Finnhub company profiles lack industry data.
- Plaid is configured for Sandbox by default. Production requires approved Plaid
  access and production credentials.
- Natural-language criteria and explanations require OpenAI. Deterministic stock
  and portfolio analysis remains usable when AI is unavailable.
- Historical indicators are not mixed into the fundamental scoring weights.
- No broker is configured and no live or simulated order is reported as filled.
